# FocusGlass: правила для тестера

## Общие правила

- Проверять именно `FocusGlass.app` из `FocusGlass-0.0.4.zip`, а не запуск из
  исходников через `swift run`.
- Перед первым запуском проверить контрольную сумму архива командой из
  `README.md`.
- Если используешь существующие данные FocusGlass, сначала сделай резервную
  копию: скопируй папку `~/Library/Application Support/FocusGlass` в безопасное
  место.
- Для чистого прогона можно временно переименовать папку данных FocusGlass.
- Один отчётный пункт = одна проблема или одно UX-наблюдение.
- Серьёзность проблемы указывать одним из уровней: `blocker`, `high`,
  `medium`, `low`.
- К каждому пункту прикладывать скриншот.
- Если проблема связана со Strict Mode, указать правило, действие правила,
  приложение или сайт, и состояние системных разрешений.
- Если проблема связана с переносом данных или хранилищем, указать: это чистый
  профиль или уже существующие данные FocusGlass.
- Предупреждение macOS из-за локально подписанной сборки, которая не проходила
  notarization (проверку Apple), не считается багом FocusGlass, но его можно
  отметить отдельной заметкой.

## Словарь терминов

- `checksum` / контрольная сумма - короткая проверка, что архив не повреждён и
  совпадает с подготовленной сборкой.
- `ad-hoc signed` / локально подписанная сборка - приложение подписано для
  тестирования, но не как публичный релиз через Developer ID.
- `notarized` / notarization - проверка Apple для публично распространяемых
  macOS-приложений. В этой tester-сборке её нет, поэтому macOS может показать
  предупреждение при первом запуске.
- `backup` / резервная копия - копия папки данных FocusGlass перед тестом,
  чтобы можно было вернуть проекты, задачи и настройки.
- `permissions` / системные разрешения - разрешения macOS, например
  Notifications, Accessibility и Automation.
- `Automation permissions` - разрешение macOS на автоматизацию других
  приложений. Для FocusGlass оно важно при проверке правил сайтов в браузере.
- `Strict Mode` / строгий режим - режим, в котором FocusGlass реагирует на
  отвлекающие приложения или сайты.
- `warn`, `hide`, `pause` - действия Strict Mode: предупредить, скрыть
  отвлекающее окно или поставить таймер на паузу.
- `blocker` - проблема, из-за которой нельзя продолжать основной тест.

## Что считать blocker

- Приложение не запускается.
- Нельзя пройти первый экран или путь выдачи системных разрешений.
- Таймер не стартует или падает.
- Данные проектов/задач теряются после перезапуска.
- Settings или главное окно полностью ломают основной путь.
- Strict Mode делает приложение непригодным для тестирования.

## Что прислать

- Заполненный `tester-report-template.md`.
- Папку `screenshots/`.
- Для blocker/crash: скриншот, текст ошибки и шаги воспроизведения первыми
  пунктами.
