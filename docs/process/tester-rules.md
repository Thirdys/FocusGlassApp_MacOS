# FocusGlass: правила для тестера

Этот документ является source-копией правил из исторической ветки
`tester/0.0.4`. Для следующей tester delivery его нужно проверить вместе с
новой сборкой и cumulative checklist.

## Общие правила

- Проверять именно `FocusGlass.app` из tester-архива, а не запуск из исходников
  через `swift run`.
- Перед первым запуском проверить контрольную сумму архива командой из
  tester `README.md`.
- Если используются существующие данные FocusGlass, сначала сделать резервную
  копию папки `~/Library/Application Support/FocusGlass`.
- Для чистого прогона можно временно переименовать папку данных FocusGlass.
- Один отчётный пункт = одна проблема или одно UX-наблюдение.
- Серьёзность указывать как `blocker`, `high`, `medium` или `low`.
- К каждому пункту прикладывать скриншот.
- Для Strict Mode указать правило, действие, приложение/сайт и состояние
  системных разрешений.
- Для persistence/migration указать, использовался чистый профиль или
  существующие данные.
- Предупреждение macOS из-за локально подписанной сборки без notarization не
  считается багом FocusGlass, но его можно отметить отдельной заметкой.

## Словарь терминов

- `checksum` / контрольная сумма - проверка, что архив не повреждён и совпадает
  с подготовленной сборкой.
- `ad-hoc signed` / локально подписанная сборка - приложение подписано для
  проверки целостности и тестирования, но не Developer ID для публичного
  релиза.
- `notarized` / notarization - проверка Apple для публично распространяемых
  macOS-приложений. В текущем tester-канале её нет, поэтому macOS может показать
  предупреждение при первом запуске.
- `backup` / резервная копия - копия папки данных FocusGlass, из которой можно
  восстановить проекты, задачи и настройки.
- `permissions` / системные разрешения - разрешения macOS, например
  Notifications, Accessibility и Automation.
- `Automation permissions` - разрешение на управление другим приложением. Оно
  нужно FocusGlass для чтения адреса активной вкладки поддерживаемого браузера.
- `Strict Mode` / строгий режим - режим реакции на отвлекающие приложения и
  сайты во время активной focus-сессии.
- `warn`, `hide`, `pause` - предупредить, скрыть отвлекающее приложение/браузер
  или поставить текущую сессию на паузу.
- `blocker` - проблема, из-за которой основной тест нельзя продолжить.

## Что считать blocker

- Приложение не запускается.
- Нельзя пройти первый экран или путь выдачи системных разрешений.
- Таймер не стартует или приложение падает.
- Проекты/задачи теряются после перезапуска.
- Settings или главное окно полностью ломают основной путь.
- Strict Mode делает приложение непригодным для дальнейшего тестирования.

## Что прислать

- Заполненный `tester-report-template.md`.
- Папку `screenshots/`.
- Для blocker/crash: скриншот, текст ошибки и шаги воспроизведения первыми
  пунктами.
